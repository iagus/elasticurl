# elasticurl

[![CI](https://github.com/iagus/elasticurl/actions/workflows/ci.yml/badge.svg)](https://github.com/iagus/elasticurl/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

A tiny, fast CLI for everyday Elasticsearch operations — no more memorizing
endpoint paths.

`elasticurl` wraps the requests you make most often against a local (or remote)
Elasticsearch: listing indices, checking cluster health, inspecting mappings
and index sizes, listing aliases, and querying an index. It's a single
**~1.4 MB static binary** with sub-millisecond startup, and its `--help`, man
pages and shell completions are all generated from one source, so they never
drift apart.

```console
$ elasticurl health
active_shards: 12
cluster_name: docker-cluster
number_of_nodes: 3
status: green
unassigned_shards: 0

$ elasticurl indices
health status index   docs.count store.size pri.store.size
green  open   logs         1000      208kb         104kb
yellow open   metrics       500      100kb         100kb

$ elasticurl mappings logs
field        type
@timestamp   date
msg          text
msg.keyword  keyword

$ elasticurl query logs -q 'status:404' -n 3
total: 42
_index  _id  _score  _source
logs    1    1.5     {"msg":"hello"}
logs    2    1.0     {"msg":"world"}
```

## Features

- **Table output by default**, using Elasticsearch's native `_cat` formatting;
  switch to `-o json` (with optional `--pretty`) for piping into `jq`
- **Six subcommands** covering the most common endpoints (see table below)
- **Lucene or full Query DSL**: `-q 'status:404'`, `-f query.json`, or pipe a
  body through stdin (`-f -`); plain `query <index>` is a `match_all`
- **Connection via flag or env var**: `-H/--host` (`ELASTIC_URL`),
  `-u/--user user:pass` (`ELASTIC_AUTH`)
- **Elasticsearch error reasons surfaced**, e.g.
  `elasticurl: error: Elasticsearch error 404 Not Found: no such index [logs]`
- **Man pages and shell completions** generated from the CLI definition

## Commands

| Command | Elasticsearch request |
|---|---|
| `elasticurl health` | `GET /_cluster/health` |
| `elasticurl indices` | `GET /_cat/indices?v` |
| `elasticurl size [index]` | `GET /_cat/indices[/<index>]`, biggest first |
| `elasticurl mappings <index>` | `GET /<index>/_mapping` rendered as a field/type table |
| `elasticurl aliases` | `GET /_cat/aliases?v` |
| `elasticurl query <index> [-q QUERY \| -f FILE] [-n N]` | `GET`/`POST /<index>/_search` |
| `elasticurl completions <shell>` | prints bash/zsh/fish completions to stdout |

### Global flags

| Flag | Env var | Default | Description |
|---|---|---|---|
| `-H, --host <URL>` | `ELASTIC_URL` | `http://localhost:9200` | Elasticsearch base URL |
| `-u, --user <USER:PASS>` | `ELASTIC_AUTH` | — | Basic auth credentials |
| `-o, --output <FMT>` | | `table` | `table` or `json` |
| `--pretty` | | off | Pretty-print JSON output |
| `-v, --verbose` | | off | Print request/response lines to stderr |

## Installation

### Prebuilt binaries

Download a ready-made binary for Linux (x86_64/aarch64, statically linked with
musl) or macOS (Intel/Apple silicon) from
[Releases](https://github.com/iagus/elasticurl/releases) — each archive also
bundles the man pages under `man/`.

### From source

Requires a [Rust toolchain](https://rustup.rs/) (1.85+):

```sh
git clone https://github.com/iagus/elasticurl && cd elasticurl
cargo install --path .            # installs elasticurl into ~/.cargo/bin

# or just build
cargo build --release             # binary: target/release/elasticurl
```

## Getting help

Every command and flag is documented in `--help`:

```sh
elasticurl --help
elasticurl query --help
```

Man pages for `elasticurl` and each subcommand are generated by `build.rs`
into `man/` at build time:

```sh
man -l man/elasticurl.1
man -l man/elasticurl-query.1
# or install system-wide:
sudo install -m 644 man/*.1 /usr/local/share/man/man1/
```

Shell completions:

```sh
elasticurl completions bash | sudo tee /etc/bash_completion.d/elasticurl
elasticurl completions zsh  > "${fpath[1]}/_elasticurl"
elasticurl completions fish > ~/.config/fish/completions/elasticurl.fish
```

## Development

```sh
cargo build
cargo test          # unit tests + mock-server (wiremock) client tests
```

```
src/
├── main.rs         # arg parsing → dispatch
├── cli.rs          # clap definitions: single source for --help and man pages
├── client.rs       # minimal blocking ES HTTP client (ureq)
├── output.rs       # table / kv / hits / mappings rendering
└── commands/       # one small module per subcommand
```

The release profile is tuned for binary size (`opt-level = "z"`, LTO,
`codegen-units = 1`, `panic = "abort"`, `strip`) → ~1.4 MB stripped binary.

CI runs `cargo fmt`, `cargo clippy` and `cargo test` on every push and PR.
Pushing a `v*` tag builds release binaries for Linux (static musl) and macOS
(both architectures) and attaches them, along with the man pages, to the
GitHub release; it then also bumps the formula in
[iagus/homebrew-tap](https://github.com/iagus/homebrew-tap) to the new tag
automatically (requires a `HOMEBREW_TAP_TOKEN` secret with write access to
the tap repo). A release can be (re)built for an existing tag from the
Actions tab via the "Release" workflow's manual dispatch.
